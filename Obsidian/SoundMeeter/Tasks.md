- [x] Есть задержка звука (особенно на канале с музыкой это заметно). При остановке любого воспроизведения звук пропадает и начинается через какой-то промежуток времени (стало заметно на задержке в 1 секунду) - КРИТИЧНО: для звука с игр, микрофона и других источников. Одновременно на нескольких каналах такая задержка не наблюдается.
	- **Настоящая причина — не буферы устройств, а `RingCursor`.** Каждый `BusTap` держит свой курсор над общим кольцом, и новый курсор стартовал с `_nextRead = 0` — позицией в шкале кольца с момента его создания. Для кольца, которое уже переполнялось, `Read` считал `start = max(0, written − Capacity)`, то есть **молча отдавал целую секунду устаревшего звука** и навсегда оставался на секунду позади писателя. Отсюда и «застревание» остановки, и то, что перезапуск движка или полосы лечило (новое кольцо, нулевой счётчик), и то, что на нескольких каналах сразу было не видно. Правка: курсор встаёт на живую границу кольца (`SampleRingBuffer.cs`), регрессия закрыта `SampleRingBufferTests` + `BusTapTests`.
	- Попутно: захват переведён на `WasapiRecorderBuilder` (было 100 мс буфера и опрос потока по таймеру — уменьшить было нечем), вывод на `WasapiPlayerBuilder` с IAudioClient3-низкой латентностью и MMCSS; фактическая задержка пишется один раз при открытии полосы и шины — на машине автора выход дал 22 мс при норме 200+, и виновником оказалось кольцо, а не устройство. Периодическое разложение задержки по этапам добавляли для диагностики и убрали: на уровне Information оно давало спам. Константы в `AudioEngineDefaults`.

	 	- **Каналов на первом запуске создавали два независимых механизма, и убрать надо было оба.** Первый — `EnsureDefaultStrips()`: четыре пустых стрипа («Unassigned input» ×2 и «Unassigned» ×2), если списки пусты. Из-за него кнопка «Обновить устройства» и подключение новой гарнитуры тоже дописывали каналы. - [x] Компиляция в один файл
 	- **Релиз — ровно один `SoundMeeter.exe` (~69 МБ), без DLL, папок и требований к установленному .NET.** Профиль `publishProfiles/portable.pubxml`, а не свойства csproj: они значат что-то только при публикации, а в csproj включились бы и при `dotnet build`, и сборка стала бы self-contained. Опубликовать без профиля можно, но выдаётся предупреждение `SM0001` — молчаливый многофайловый выход обнаружился бы уже в релизе у пользователя.
 	- **Почему без сжатия файл был бы втрое тяжелее:** сжатый бандл 69 МБ против ~190 МБ, распаковка платит временем только на первом запуске (дальше кэш по хэшу содержимого), а качают его с GitHub Releases. Нативную `rnnoise.dll` (единственный нативный файл в приложении) пришлось забрать внутрь через `IncludeNativeLibrariesForSelfExtract` — иначе SDK выкладывает нативные файлы рядом, и «один exe» перестаёт быть одним exe. `.pdb` из сборок зависимых проектов убирает только `AllowedReferenceRelatedFileExtensions=none`: `DebugSymbols=false` их не убирает.
 	- **Обрезка (PublishTrimmed) несовместима с WPF** и не включается никогда: падало бы на любом типе, до которого не дошла статическая разведка.
 	- **Что пришлось переделать в коде:**
 	  - `UpdateApplier` требовал `SoundMeeter.dll` в архиве, то есть **любое** обновление single-file отвергалось бы как «архив неполный». Payload ровно из одного exe от 8 МБ принимается как бандл, меньший — по-прежнему отвергается, чтобы обрывок архива не прошёл;
 	  - **правило удаления сузили до «только dll/pdb».** Раньше удалялось всё, чего нет в архиве, кроме данных приложения: на single-file это значило бы снести любой файл и папку рядом с exe, положенные пользователем. Теперь единственная причина удалять файлы — остатки прежней многофайловой сборки. Обход папок оставлен (сами папки не удаляются): иначе оставшаяся старая `ru\....resources.dll` перебила бы локализацию, вшитую в новый exe, и русский интерфейс показал бы строки прошлой версии, а на новых ключах — `⟨Sm.Ключ⟩`.
 	- **`Resources/system_apps_filter.json` вернули файлом рядом с exe — его правят руками,** список системных приложений у машины свой. Встроенная копия осталась как образец: файла нет (первый запуск, удалили, каталог только для чтения) — сервис создаёт папку и файл сам; файл пользователя всегда главнее встроенной копии. Побочный грабли: файл сохранён с BOM, а `JsonSerializer` для `byte[]` преамбулу не пропускает — чтение перешло на байты, поэтому BOM снимается явно (`ReadAllText` делал это сам, пока файл читался как текст).
 	- Регрессия закрыта `UpdatePlanTests` (7: single-file принимается, маленький одинокий exe и бандл с лишним файлом отвергаются, старая многофайловая установка чистится) и `SystemAppsFilterTests` (2). Не сделано намеренно: собранный exe не запускался — приложение требует повышения прав, и UAC-запрос с запуском микшера на машине автора не стоит того; это единственный ручной шаг, который стоит сделать перед релизом.
